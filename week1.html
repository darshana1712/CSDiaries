Git and GitHub for Absolute Beginners

Week 1 · October 2026

Imagine writing an assignment and saving copies like final.docx, final2.docx, final_REAL.docx. Now imagine ten people doing that on the same project. That mess is the problem Git solves. This week I learned how it works, and I used it to publish this very blog.

Git vs GitHub

These two names are often mixed up, but they are different things.

  • Git is a tool installed on your computer. It tracks every change you make to your files, like save points in a video game.
  • GitHub is a website that stores your Git projects online, so you can back them up, share them, and work with others.

Git works without GitHub. GitHub is just a convenient place to keep your Git projects.

Key words to know

  • Repository (repo): a project folder that Git is tracking.
  • Commit: a saved snapshot of your project, with a message describing what changed.
  • Branch: a separate line of work. The default one is usually called main.
  • Remote: the online copy of your repo (on GitHub).
  • Push / Pull: push sends your commits to GitHub; pull brings new changes from GitHub to your computer.

The three-step workflow

Every change you save follows the same path: edit files, stage them (choose what goes into the snapshot), then commit them (take the snapshot). Think of it as putting items in a box, then sealing the box with a label.

Setting up Git

After installing Git, tell it who you are. This is done once:

git config --global user.name "Your Name"
git config --global user.email "you@example.com"

Your first repository

Open a terminal inside your project folder and run:

git init                    # start tracking this folder
git status                  # see what changed
git add .                   # stage all changes
git commit -m "first version"   # save the snapshot
git log --oneline           # view your history

git status is the command I used most while learning. It tells you what Git sees and what to do next.

Sending it to GitHub

First create an empty repository on GitHub (click New repository). Then connect your folder to it and push:

git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/my-blog.git
git push -u origin main

The -u only matters the first time. After that, git push is enough.

Daily routine

Once everything is set up, saving your work online takes three commands:

git add .
git commit -m "describe what you changed"
git push

Branches in one minute

A branch lets you try something new without touching your working code. If the experiment works, you merge it back. If not, you delete the branch and nothing is lost.

git branch new-feature       # create a branch
git checkout new-feature     # switch to it
git checkout main            # go back
git merge new-feature        # bring the changes into main

Mistakes I made

  • Forgetting to commit before pushing. git push only sends commits, not unsaved changes. Run git status first.
  • Vague commit messages like "update". Write what actually changed, for example "add Week 1 post".
  • Creating the GitHub repo with a README, then pushing a local repo. The two histories clash. Start with an empty repo if you already have local files.
  • Typing the wrong remote URL. Check it with git remote -v.

Publishing with GitHub Pages

GitHub can host a static website for free. In your repo, open Settings → Pages, choose the main branch, and save. After a couple of minutes your site is live at https://YOUR-USERNAME.github.io/my-blog/. Every time you push, it updates automatically.
